# kulman

**kulman** читається «кульман»: кульман — креслярська дошка конструкторського бюро; тут це вхідні
двері набору: він встановлює інструменти й налаштовує проєкт.

[![CI](https://github.com/bambooplanedev/kulman/actions/workflows/rust.yml/badge.svg?branch=main)](https://github.com/bambooplanedev/kulman/actions/workflows/rust.yml)
[![Release](https://img.shields.io/github/v/release/bambooplanedev/kulman)](https://github.com/bambooplanedev/kulman/releases)
[![Rust 1.90+](https://img.shields.io/badge/rust-1.90%2B-orange?logo=rust)](https://www.rust-lang.org)
[![License: MIT](https://img.shields.io/badge/license-MIT-blue)](LICENSE)

kulman — набір інструментів для агентів, що пишуть код, і людей, які з ними працюють; назви взято
з креслярських дошок і плазів авіаційного конструкторського бюро. `calque` компілює проєкт у карту,
в якій агент може шукати, — де лежить кожна функція, хто її викликає, які рядки читати, — а `plaz`
малює справжні рішення кожної функції, щоб їх читали люди. Жоден не викликає модель: ті самі
джерела дають побайтово той самий результат, а `kulman` встановлює обидва й налаштовує їх у проєкті
однією командою на кожен крок.

## Навіщо

Щоб людина й агент працювали з однією й тією самою картиною проєкту. Людині вона потрібна, щоб
розуміти бізнес-логіку, тобто що відбувається і за яких умов, і ставити агентові точні завдання.
Агентові — щоб знаходити потрібне, не витрачаючи токени на зайве читання. `calque` і `plaz`
будують цю картину з коду, без мовної моделі, з однаковою точністю: до рядка й до умови.

`plaz` малює для кожної функції схему рішень з умовами, дослівно взятими з коду, і показує, куди
веде кожен виклик. Гілки не треба тримати в голові: вони перед очима. Він для людини: його
налаштування нічого не реєструє для агентів.

`calque` дає агентові пошук у проєкті: де лежить потрібне і хто викликає функцію. Коли агент мусить
сам знайти код, у лабораторному тесті calque приблизно вдвічі здешевив пошук для сильних моделей;
коли завдання вже називає файл, він заощаджує мало ([що виміряно](#що-заощаджує-calque-і-коли)).

`kulman` встановлює й оновлює обидва однією командою і перевіряє підпис релізу.

## Що заощаджує calque і коли

Кожна цифра чинна лише за умов, названих поруч із нею; як міряли і більше цифр — у
[README calque](crates/calque/README.uk.md#виміряне).

**Пошук без названого файлу.** Девʼять питань «де X і яке значення воно використовує» на фікстурі
C++, написаній для тесту: файли з відповіддю по 530–645 рядків і їхні копії, доповнені до 1 500 і
5 000 рядків. Запити називають компонент («risk engine»), але не файл. По 135 прогонів на модель і
варіант, з calque і без нього, на тестовому стенді, а не в Claude Code; вартість — за
прейскурантом, з кешуванням промпту:

| модель | вартість одного пошуку | вхідні токени | правильних, без / з calque |
|---|---|---|---|
| Claude Sonnet 5.5 | −54% | −29%, статистично не відрізняється від нуля | 135 / 135 |
| Claude Opus 5.5 | −51% | −21%, статистично не відрізняється від нуля | 135 / 135 |

Заощадження росло з розміром файлу: від −38…−40% на файлах початкового розміру до −59…−63% на 5 000 рядках.
Без calque ці моделі й так спершу шукають grep, а тоді читають діапазон; calque заощаджує їм ходи
й новий контекст, який додає кожен хід, а не прочитані рядки. Слабші моделі читають файли цілком,
коли не знають, де шукати: без calque цілими файлами було 17% (Claude Haiku 5.5), 46%
(deepseek-v4.1-flash) і 58% (qwen3.8-27b) їхніх читань коду, з ним — 4–10%. Їхні вхідні токени
впали на 29%, 36% і 75% за всіма трьома розмірами (на 4–23% на файлах початкового розміру), а правильних
відповідей не стало більше.

**Реальна робота, де файл уже названо.** Пʼять днів трас агентів з одного проєкту: агенти Claude
Opus і Sonnet працюють за завданнями, які пише агент-оркестратор, і читають здебільшого скрипти на
Python і shell. Завдання або документ, на який воно вказує, називали файл перед 90–98% з 2 125
читань коду; агенти знаходили рядок через `grep -n` у цьому файлі й читали вікно: цілим файлом були
2,0% читань, медіанне читання — 31 рядок. Приблизно третина пошуків визначень (31,6–38,6%) йшла
через calque. Його діапазони могли б заощадити там ще приблизно 0,25–0,5% вхідних токенів. Тож у
такому режимі calque заощаджує мало: файл уже відомий, grep у ньому коштує не більше за відповідь
calque, а 30% читань — це shell-код поза функціями, для якого calque не дає діапазону. Заощадження
на реальній роботі не виміряно. Надійність на тих самих трасах: 1 помилка на 260 викликів, медіанний
час відповіді 10–12 мс, і жодне з 17 читань, що почалися з повернутого рядка, не натрапило
на те, що коду там уже немає.

**Чи користуються агенти calque.** Цей блок про використання; вартість — у наступному. У контрольних прогонах
у повному Claude Code (headless, із завантаженими інструкціями користувача й проєкту, скілами та
плагінами; Claude Sonnet 5.5, calque 0.8.1; 26 прогонів на пошук за іменами і 26 на завдання, що
називає файл і просить невелику правку) calque був першим пошуком агента у 26 з 26 і 26 з 26
прогонів, і кожне завдання виконано; той самий набір завдань в ізольованому стенді дав 52 з 52.
Преамбула приблизно в сім разів більша використання не знизила. У живій роботі на одному проєкті
(головний агент, що ставить завдання підлеглим, 2026-11-10 — 2026-11-17) calque був першим пошуком у
29 з 83 головних агентів Opus, 44 зі 142 підлеглих Opus і 20 зі 150 підлеглих Sonnet. У тих сесіях
інструменти й інструкції сервера були завантажені, і різниці не пояснюють ні більший контекст Claude
Code, ні завдання, що називає файл і просить правку (0 пунктів, 95% інтервал від −13 до +13, по 26
прогонів у групі). Причина невідома. Ще не перевірено: пошуки, які роблять підлеглі агенти, запущені
головним (жоден із 52 контрольних прогонів не делегував), довгі сесії та цілі, що надходять не як
список імен.

**Вартість у повному Claude Code, на контрольних завданнях.** Ті самі прогони Sonnet 5.5 (calque 0.8.1,
повний Claude Code без інтерфейсу) порівняно з контролем без calque: без сервера й без рядків про
calque в інструкціях проєкту та в завданні; по 26 прогонів у групі й формі завдання, на готовому
списку точних імен в одному дереві коду. Для пошуку за іменами вартість успішного прогону впала на
26% (95% інтервал від −37% до −16%; $0,064 проти $0,087), приблизно на два ходи менше й приблизно на
8 секунд швидше (5,1 с проти 12,9 с); правильних відповідей 26 з 26 з calque і 24 з 26 без нього. Для
завдання, що називає файл і просить невелику правку, вартість успішного прогону зросла на 15%
(інтервал від +10% до +19%; $0,147 проти $0,128), приблизно на 3,4 ходу більше; правильних 26 з 26 в
обох варіантах. Приблизно половина зайвої вартості — постійні витрати calque (визначення його
інструментів та інструкції додають 1 744 токени до кожного запиту, з кешуванням приблизно $0,007 на
прогін пошуку і $0,010 на прогін правки, вони вже враховані в цих цифрах); решта — те, як агент
правив: з calque він читав кожен повернутий діапазон і робив одну правку на елемент, без нього часто
робив один grep і одну правку скриптом. Жодна група не читала файл цілим, ні з calque, ні без нього,
тож заощадження на пошуку дають менше ходів, менше кешованого контексту, прочитаного знову, і менше
виводу, а не уникнуті читання. Прогони з calque зроблено раніше того ж дня, а не вперемішку з
контролем, а в завданні з правкою разом із calque прибрано й рядок завдання про читання лише
повернутих діапазонів, тож інструмент і цю вказівку не розділено.

**Підказка до запиту.** На звичайних запитах двох авторів (1 514 і 136 запитів) підказка спрацьовувала
на 67% і 49% із них, а з 77 підказок, показаних під час реальної роботи, лише одна правдоподібно
привела агента до файлу, якого він ще не мав. Тож налаштування додає її тільки з `--hook`. Два
фільтри тепер знижують частоту до 36% і 27%; на запитах, схожих на розмову, підказка досі
зʼявляється приблизно в третині випадків (37% і 27%).

**Коли це допомагає:**

- Допомагає, коли пошук і є завданням: файл не названо, файли великі, моделі слабші або треба знайти
  список імен (−26% на завдання пошуку в повному Claude Code). Сильні моделі заощаджують ходи, а не
  прочитані рядки.
- Допомагає мало, а може трохи й коштувати, коли пошук — мала частина правки у вже названому файлі
  (+15% на завданні з правкою вище).
- Нічого не дає для дослівного тексту, регулярних виразів, усіх входжень рядка чи підрахунків: це
  й далі робота grep.
- Не охоплює shell-код поза функціями і скрипти без розширення для інтерпретаторів, крім `sh` і
  `bash`.

**Межі доказів.** Набір пошуків написаний самостійно й синтетичний, з доповненими файлами й запитами,
що називають компонент; цифри −54% і −51% отримано на ізольованому стенді. У повному Claude Code і
використання, і вартість виміряно на Sonnet, на контрольних завданнях, цілями яких був готовий список
точних імен. Контрольні прогони й траси живої роботи — з одного дерева коду, жива робота — з однієї
команди, контрольні прогони — з однієї моделі.
Щоб казати, як часто агенти користуються calque в реальній роботі, потрібна більша вибірка з
незалежних проєктів. Заощадження на реальній роботі не показано.

## Встановлення

Сам `kulman` завантажується одним рядком:

    curl --proto '=https' --tlsv1.2 -sSfL https://github.com/bambooplanedev/kulman/releases/latest/download/install.sh | sh

Скрипт завантажує архів `kulman` для вашої системи, перевіряє його за `SHA256SUMS` релізу (і
зупиняється, якщо немає ні `sha256sum`, ні `shasum`) та кладе бінарник у `~/.kulman-home/bin/kulman`.
Більше він нічого не записує і не змінює профілів оболонки. Додайте `~/.kulman-home/bin` у свій
`PATH` самі, якщо хочете набирати `kulman` у терміналі; агенти знаходять `calque` і без цього, а коли
`~/.local/bin` уже в `PATH`, `kulman install` лінкує туди інструменти. Релізи підписані: `install.sh` перевіряє підпис
`SHA256SUMS`, якщо встановлено `minisign`, а `kulman` перевіряє кожен реліз, який читає (див.
[Перевірка релізу](#перевірка-релізу)).

Далі встановіть модулі:

    kulman install

Ця команда кладе `calque` і `plaz` (модулі релізу за замовчуванням) у `~/.kulman-home/bin`, поруч із
`kulman`, а в `~/.kulman-home` — `manifest.json` релізу і `state.json`. Поза цією текою нічого не
записується. Потім у кожному проєкті:

    cd your-project
    kulman setup --scope repo

Ця команда запускає там `calque setup` і `plaz setup`. Вони пишуть у теку проєкту `.kulman/` (вікі,
а карту — у `.kulman/map/`), додають конфіги агентів для знайдених агентів (хук запиту — лише з `--hook`), створюють
`.agents/memory/` для нотаток агентів і додають `.kulman/` у `.gitignore`. `--scope repo` пише
закомічені файли для всієї команди. `--scope local` пише свої файли лише в цю робочу копію й
натомість вносить створені ним у `.git/info/exclude`; виняток — сервер calque для Claude Code: його
додає `claude mcp add-json … --scope local` у власну конфігурацію Claude Code, і для цього потрібен
CLI `claude`. Сервер для Codex за будь-якого `--scope` потрапляє у власний `.codex/config.toml`
проєкту, і Codex завантажує його лише в проєкті, якому довіряє.

Згодом `kulman update` доводить усе до останнього релізу, `kulman setup --scope repo --remove`
скасовує налаштування проєкту (з тим самим `--scope`, з яким його налаштовували), а `kulman remove`
видаляє те, що встановив kulman. Команди, прапорці, коди виходу й будова релізу:
[crates/kulman/README.uk.md](crates/kulman/README.uk.md).

### Нехай це зробить ваш агент

Якщо не хочете виконувати ці кроки вручну, вставте це у чат свого агента для програмування:

    Install or update kulman in this project by following
    https://raw.githubusercontent.com/bambooplanedev/kulman/main/docs/agent-setup.md
    Ask me before installing, updating, or changing any file outside this agent's own configuration.

Заздалегідь прочитайте [docs/agent-setup.md](docs/agent-setup.md), щоб побачити, що скажуть агентові.

### Перевірка релізу

`manifest.json` і `SHA256SUMS` релізу підписані через minisign ключем релізів,
[`release/kulman.pub`](release/kulman.pub); кожен архів перевіряється за сумами SHA-256 у них.
`kulman` відхиляє реліз, підпис якого не проходить перевірку або, через `https://`, відсутній;
`install.sh` перевіряє підпис, якщо встановлено `minisign`, а інакше каже, що не перевірив. Ключ,
команди для перевірки релізу вручну, те, як реліз підписують, і обмеження:
[Підписи](crates/kulman/README.uk.md#підписи).

## Модулі

**[kulman](crates/kulman/README.uk.md)** встановлює, оновлює й видаляє модулі та запускає їхнє
налаштування в проєкті. Це інсталятор, а не модуль.

**[calque](crates/calque/README.uk.md)** компілює проєкт — код, нотатки, документацію — у вікі з
перехресними посиланнями в Markdown і карту символів з діапазонами рядків і віддає її агентам через
MCP: `search` відповідає рядками `path:start-end`, `callers` каже, хто викликає функцію.
`calque setup` підключає її до Claude Code, pi, Cursor і Codex. У її README — CLI, MCP-сервер,
памʼять агента, формат результату й виміри.

**[plaz](crates/plaz/README.uk.md)** для кожної функції пише сторінку Markdown з блок-схемою рішень:
буквальна умова кожної гілки, хто викликає функцію і куди веде кожен виклик. Схеми є для Rust,
Python, C і C++; інші мови отримують примітку «not covered yet». Карта — для людей: `plaz setup`
нічого не каже про неї агентам.

**[techlog](crates/techlog/README.md)** — бібліотека: де лежить памʼять агентів — `.agents/memory/`
проєкту й теки, які агенти тримають поза ним, — і хто останнім змінив кожну закомічену нотатку. Нею
користується calque. README англійською.

**[wiki-code](crates/wiki-code/README.md)** — бібліотека, спільна для calque і plaz: обходить дерево
джерел, видобуває функції й типи через tree-sitter, індексує виклики й імпорти. README англійською.

## Вимоги

- Реліз працює на macOS на Apple silicon (`aarch64-apple-darwin`) і на Linux x86_64
  (`x86_64-unknown-linux-musl`). Збірка для Linux статична й працює однаково на системах із glibc і
  з musl. Інших збірок немає; на будь-якій іншій системі, зокрема на Mac з Intel, збирайте з коду.
  Windows не підтримується.
- `install.sh` потребує `curl`, `tar`, `mktemp` і `sha256sum` або `shasum`.
- Для агентів: MCP-клієнт — Claude Code, pi, Cursor, Codex, Claude Desktop чи інший. Див.

## Збірка з коду

Для збірки потрібен Rust 1.90 чи новіший; для тестів — ще й `git`, `jq` та
користувач без прав root.

    git clone https://github.com/bambooplanedev/kulman
    cd kulman
    cargo install --path crates/calque      # у ~/.cargo/bin
    cargo install --path crates/plaz
    cargo install --path crates/kulman

    cargo test
    cargo clippy --all-targets -- -D warnings
    cargo fmt --check

`cargo install` кладе бінарники в `~/.cargo/bin`. На двох системах, для яких є реліз, `kulman`,
зібраний так, встановлює модулі з опублікованого релізу. На будь-якій іншій системі він цього не
може: збірки для неї немає, і `kulman install` зупиняється з `no build for <os>/<arch>`. Там
користуйтеся зібраними тут `calque` і `plaz` і запускайте їхній власний setup у кожному проєкті
(`calque setup --scope repo`, `plaz setup --scope repo`). Власні тести kulman встановлюють реліз,
тож їм теж потрібна одна з цих двох систем. Пуш тегу `v*`, що збігається з версією робочого
простору, збирає архіви для macOS і Linux, перевіряє, що вони встановлюються, і створює чернетку
GitHub Release з їхніми `SHA256SUMS`; власник підписує чернетку через `scripts/release-sign.sh` і
потім публікує її ([Підписи](crates/kulman/README.uk.md#підписи)).
