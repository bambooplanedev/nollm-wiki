# plaz

**plaz** читається «плаз»: плаз — підлога, на якій конструкторське бюро викреслює справжні лінії
планера в натуральну величину; тут це справжні рішення кожної функції.

`plaz` малює справжні рішення кожної функції: для кожної функції — сторінка Markdown з блок-схемою рішень (Mermaid), де стоїть буквальна умова кожного `if`, гілки `match` і циклу, прикріплені до неї коментарі, хто викликає функцію і куди веде кожен виклик. Жодна модель не викликається: ті самі джерела дають побайтово ті самі сторінки.

Це модуль [набору kulman](../../README.uk.md), поруч із [kalka](../kalka/README.uk.md). Він залежить від `wiki-code` з цього робочого простору за шляхом і ні від чого з вікі kalka. Його версія — версія робочого простору.

**Попередня версія.** Схеми є для Rust і Python; інші мови отримують примітку «not covered yet». `kulman install` встановлює його разом із релізом (див. [Встановлення](../../README.uk.md#встановлення)); як зібрати самому — нижче.

## Збірка

    cargo build --release      # ../../target/release/plaz, у корені робочого простору
    cargo test

## Команди

    plaz build [--source DIR] [--vault DIR]
    plaz setup [--source DIR] --scope repo|local [--remove]

`plaz build` читає код у `--source` (за замовчуванням `.`) і пише сторінки в `<source>/.kulman/map/` або в `map/` у `--vault`. Сторінки мають front matter `tags: ["plaz"]` і `kind: map`; файл на шляху сторінки без нього лишається як є і потрапляє в підрахунок. Незмінені сторінки не переписуються, сторінки файлів, яких уже немає, видаляються, а результат однаковий на кожному запуску. Дерево без жодного файлу коду лишає теку як є і видає попередження. Посилання на код стають вікі-посиланнями на сторінки коду kalka, коли сховище містить скомпільовану вікі kalka, а інакше — простими `path:start-end`.

`plaz setup` будує карту й стежить, щоб git ігнорував `.kulman/`:

- `--scope repo` додає рядок `.kulman/` у `<source>/.gitignore`, спільний для команди.
- `--scope local` додає його в `info/exclude` репозиторію, лише для цієї копії. Поза репозиторієм git команда будує карту, пише `not a git repository: nothing to exclude` і не змінює жодного файлу.
- Рядок у будь-якому з цих файлів зараховується: двічі нічого не додається.
- `--remove` видаляє лише власні сторінки карти й теки, що лишилися порожніми під `.kulman/map/`, разом із самою `map/`, коли вона спорожніє; рядок ігнорування лишається, а файлів kalka в `.kulman/` команда не чіпає.

`plaz setup` і `kalka setup` можуть працювати в одному проєкті: кожна команда тримається своїх сторінок.
