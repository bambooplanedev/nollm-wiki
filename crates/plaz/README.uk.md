# plaz

**plaz** читається «плаз»: плаз — підлога, на якій конструкторське бюро викреслює справжні лінії
планера в натуральну величину; тут це справжні рішення кожної функції.

`plaz` малює справжні рішення кожної функції: для кожної функції — сторінка Markdown з блок-схемою рішень (Mermaid), де стоїть буквальна умова кожного `if`, гілки `match` і циклу, прикріплені до неї коментарі, хто викликає функцію і куди веде кожен виклик. Жодна модель не викликається: ті самі джерела дають побайтово ті самі сторінки.

Карта — для людини, якій належить код: щоб читати бізнес-логіку й ставити за нею завдання. `plaz setup` нічого не каже про неї агентам: не додає ні MCP-сервера, ні навички, ні рядка інструкцій, ні хука, а теку карти git ігнорує.

Це модуль [проєкту nollm-wiki](../../README.uk.md), поруч із [`wiki`](../wiki/README.uk.md). Він залежить від `wiki-code` з цього робочого простору за шляхом і ні від чого з вікі проєкту. Його версія — версія робочого простору.

**Попередня версія.** Схеми є для Rust, Python, C і C++; інші мови отримують примітку «not covered yet». `nollm-wiki install` встановлює його разом із релізом (див. [Встановлення](../../README.uk.md#встановлення)); як зібрати самому — нижче.

## Збірка

    cargo build --release      # ../../target/release/plaz, у корені робочого простору
    cargo test

## Команди

    plaz build [--source DIR] [--vault DIR]
    plaz setup [--source DIR] --scope repo|local [--remove]

`plaz build` читає код у `--source` (за замовчуванням `.`) і пише сторінки в `<source>/.nollm-wiki/map/` або в `map/` у `--vault`. Сторінки мають front matter `tags: ["plaz"]` і `kind: map`; файл на шляху сторінки без нього лишається як є і потрапляє в підрахунок. Незмінені сторінки не переписуються, сторінки файлів, яких уже немає, видаляються, а результат однаковий на кожному запуску. Дерево без жодного файлу коду лишає теку як є і видає попередження. Теки з назвами `third_party`, `third-party`, `vendor`, `vendored` або `node_modules` пропускаються; рядок у файлі `.ignore` (наприклад, `extern/`) пропускає будь-який інший вбудований сторонній код. Посилання на код стають вікі-посиланнями на сторінки коду `wiki`, коли сховище містить скомпільовану вікі проєкту, а інакше — простими `path:start-end`.

`plaz setup` будує карту й стежить, щоб git ігнорував `.nollm-wiki/`:

- `--scope repo` додає рядок `.nollm-wiki/` у `<source>/.gitignore`, спільний для команди.
- `--scope local` додає його в `info/exclude` репозиторію, лише для цієї копії. Поза репозиторієм git команда будує карту, пише `not a git repository: nothing to exclude` і не змінює жодного файлу.
- Рядок у будь-якому з цих файлів зараховується: двічі нічого не додається.
- `--remove` видаляє лише власні сторінки карти й теки, що лишилися порожніми під `.nollm-wiki/map/`, разом із самою `map/`, коли вона спорожніє; рядок ігнорування лишається, а файлів `wiki` в `.nollm-wiki/` команда не чіпає.

`plaz setup` і `wiki setup` можуть працювати в одному проєкті: кожна команда тримається своїх сторінок.
